# VMware与服务器实验规范

## 职责

指导VMware、Windows Server、Ubuntu及Windows
客户端的网络实验，不负责总体地址规划。

总体地址规划遵循topology-planning.md。

## 环境检查

实验开始前确认：

### 宿主机环境
- 操作系统及版本
- VMware产品及版本
- 宿主机网络连接状态
- VMware虚拟网络配置
- 可用磁盘空间及备份条件

### 虚拟机环境
- 虚拟机操作系统及版本
- 虚拟机启动状态
- 虚拟网卡及连接模式
- IP、掩码、网关、DNS
- 现有网络服务及配置
- 快照、备份和回滚条件

历史实验配置仅作为线索，
必须重新检查当前环境。

不得因为历史配置存在，
就认定当前环境仍然相同。

## VMware网络模式

Bridged：
虚拟机网卡通过宿主机选定的物理网络适配器
接入相应二层网络。实际通信能力取决于
物理网络、交换设备及网络安全策略。

NAT：
虚拟机通常通过VMware提供的NAT机制，
借助宿主机网络访问外部网络。
不代表虚拟机必然能够访问互联网。

Host-only：
通常用于宿主机与相关虚拟机之间的
隔离网络通信，不默认提供外部网络访问。

具体通信能力由实际虚拟网络配置决定。
不得仅根据模式名称推断通信一定成功。

## Windows本地状态读取

CMD：

```cmd
ipconfig /all
route print
```

PowerShell：

```powershell
Get-NetIPConfiguration
Get-DnsClientServerAddress
Get-NetRoute
```

以上命令用于读取本机已有配置和状态。

不得将读取配置与修改配置混为一谈。

## Ubuntu本地状态读取

```bash
ip -br addr
ip route
resolvectl status
```

命令不可用时先检查系统环境，
不要直接安装或修改配置。

## 主动DNS查询

示例：

```text
nslookup example.com
getent hosts example.com
```

以上查询属于主动查询，不属于本地状态读取。
遵循SKILL.md的L2授权规则及明确批准的目标范围。

getent hosts可能使用本地hosts文件、
缓存或其他名称解析来源，不保证一定向
DNS服务器发送请求；仍应按主动查询管理。

执行前必须说明：
- 查询目标名称
- 使用的工具
- 可能使用的DNS服务器或名称解析来源
- 是否可能产生外部网络请求

不得仅凭命令执行成功就认定查询
一定经过DNS服务器。

如需验证实际DNS报文，
应通过适当的抓包证据确认。

## Windows Server实验

支持：

- 静态IP与DNS
- DNS服务器角色
- 正向、反向查找区域
- DHCP作用域
- Active Directory域服务
- 域用户、组及客户端加入域

实验环境的服务配置变更通常遵循
SKILL.md的L2规则。

生产环境配置修改及其他高风险变更
遵循L3规则。

## DNS验证

1. 检查服务器地址
2. 检查DNS服务状态
3. 检查客户端DNS指向
4. 检查目标记录
5. 明确查询目标和查询工具
6. 发起经授权的查询
7. 分析响应及响应码
8. 必要时通过抓包确认实际DNS通信
9. 记录证据

注意区分：
- DNS服务运行正常
- DNS记录存在
- 客户端能够正常解析
- 实际DNS报文成功往返

这些是不同的验证目标。

## DHCP验证

1. 检查网卡及网络连接
2. 检查DHCP服务状态
3. 检查作用域启用状态
4. 检查地址池及排除范围
5. 检查地址租约
6. 检查客户端当前地址
7. 检查网关与DNS选项
8. 对照预期结果
9. 记录证据

### DHCP抓包注意事项

DHCPv4初始地址分配通常遵循DORA过程：

```text
Discover → Offer → Request → ACK
```

但客户端已经持有有效租约时，
可能直接进行续租或重新绑定，
不一定重新执行完整的DORA过程。

DHCP续租通常通过DHCPREQUEST
向服务器请求延长租约，并接收DHCPACK。

因此：
- 没有捕获Discover，不代表DHCP服务故障。
- 没有捕获Offer，不代表服务器没有正常工作。
- 应结合客户端租约、服务器作用域、
  抓包接口及捕获时机进行判断。

DHCPv6使用不同的消息交互机制，
例如Solicit、Advertise、Request和Reply，
不能直接套用DHCPv4的DORA流程。

租约释放与更新可能中断网络，
必须事先说明影响并取得授权。

执行租约释放、更新或重新获取地址前，
必须确认目标网卡、当前连接方式和恢复方案。

不得将单台虚拟机的授权扩大到其他客户端。

## 域登录验证

检查：

- 客户端DNS
- 域控制器解析
- 域加入状态
- 账户身份
- 时间同步
- 必要服务
- 相关事件日志

域用户登录成功不代表组策略全部生效。

## 实验结束标准

记录：

- 实际操作
- 命令及真实输出
- 验证目标
- 实际证据
- 异常及排查过程
- 回滚信息
- 未解决问题
- 下一步任务

明确区分用户自述、实际观察、
已验证结果和待验证事项。

不得因命令执行完成就宣布实验成功。
